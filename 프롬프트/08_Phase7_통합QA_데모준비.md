# KORAIL LINK 빌드 프롬프트 세트 — Phase 7. 통합 QA · 데모 준비

> 전제: Phase 5(필수)까지, 그리고 선택적으로 Phase 6까지 마쳤다. 지금 열어서 같이 읽을 문서: `기능_상세_스펙.md` 부록 A-7(최종 통합 테스트 시나리오), B-9(명시할 한계), 부록 D(알려진 한계).

## 목표

전체 플로우가 끊기지 않고 이어지는지 처음부터 끝까지 실제로 눌러보며 검증하고, 발표/시연에서 나올 수 있는 질문에 막히지 않도록 "이건 시뮬레이션입니다"를 정직하게 정리해둔다.

## 11-1. 통합 테스트 시나리오 — 부록 A-7 그대로 실행

아래 17단계를 **하나의 Case로 끊지 않고** 실제로 눌러서 통과하는지 확인한다. 하나라도 막히면 그 앞 Phase로 돌아가서 고친다.

1. 새로운 Case 생성
2. 화물 기본정보 입력
3. 구간별 원가를 이용해 견적 생성
4. 견적 확정
5. 구간별 운임 Cost Ledger 저장 확인
6. 계약 화면 진입
7. 노선/조건 기반 특약 추천과 근거 확인
8. 담당자가 특약 선택·수정
9. 계약서 초안 생성
10. Packing List 등 문서 업로드
11. Case 정보와 추출값 비교
12. 다른 값이 있으면 담당자가 반영 여부 선택
13. 변경된 Case 정보가 이후 화면에도 유지되는지 확인
14. Invoice 업로드
15. Cost Ledger와 Invoice 항목별 비교
16. 차액 및 신규 비용 탐지
17. 정산 결과 확인

이어서 아래도 같은 Case로 확인한다(스펙 다른 섹션에서 다뤘지만 시나리오에 명시적으로 없던 것들):

18. 세금계산서 자동 생성 → Invoice 총액과 공급가액 일치 확인
19. 이의제기 챗봇에 "왜 비싸요"/"차액이 얼마예요" 질문 → 근거 포함 답변 확인
20. 전자서명 요청 → 완료 상태 전환 확인
21. 대시보드로 돌아가서 이 Case가 상태별 분포·최근 Case 목록에 반영됐는지 확인

## 11-2. 다른 노선/시나리오로 최소 1회 더

TCR 비경유 노선(중국 내륙 직통)으로 같은 시나리오를 한 번 더 돌려서, TCR 경유 노선과 특약·시황 카드·계약 조항 개수가 실제로 다르게 나오는지 확인한다. 하나의 Case로만 테스트하면 routeData 분기 버그를 놓친다.

## 11-3. 알려진 한계 정리 — 화면과 발표자료 양쪽에

`기능_상세_스펙.md` B-9와 부록 D의 항목들을 지금 만든 앱 기준으로 다시 점검하고, 아직 시뮬레이션인 부분을 화면에서 숨기지 않는다.

- 문서 업로드가 실제 파일을 안 읽는 부분(Phase 6에서 5번을 안 했다면) — 문서 화면에 "AI 추출 시뮬레이션" 배지를 붙인다.
- 전자서명이 상태 전환 시뮬레이션이라는 점 — 서명 화면에 문구로 명시.
- 세금계산서가 홈택스 발행이 아니라 미리보기라는 점.
- 이의제기 챗봇이 실시간 LLM이 아니라면(Phase 6에서 6번을 안 했다면) 그 사실.
- Phase 6에서 일부만 실연동했다면, 정확히 어떤 지표가 실시간이고 어떤 게 아직 목업인지 발표자료에 한 문장으로 정리한다 — 질의응답에서 "이거 진짜예요?"라는 질문에 즉답할 수 있어야 한다.
- `/cases`, `/contracts` 등 URL을 직접 새로고침하면 안 된다는 제약이 남아있다면(SPA 라우터 구조를 그대로 썼다면) 시연 중 실수로 새로고침하지 않도록 팀 내부에 공유한다.

## 11-4. 데모 대본 체크리스트

- [ ] "문제 상황"(서비스개요 2장) → "왜 다른가"(5장 경쟁 비교) → 실제 화면 시연 순서로 5분 내외 대본을 짠다.
- [ ] 시연은 diffPct가 음수인 케이스(비타협 원칙 위반 시 바로 티가 나는 지점)와 양수인 케이스를 각각 1개씩 준비해서, σ 판정이 대칭으로 동작한다는 걸 직접 보여준다.
- [ ] TCR 경유/비TCR 노선 두 Case를 미리 만들어두고, 계약 특약 개수 차이를 시연 포인트로 쓴다.
- [ ] 정산 화면에서 "계약 미등록 신규 항목"(BAF·서류비 등)이 뜨는 Invoice를 미리 준비해서, 총액 비교가 아니라 항목별 비교라는 차별점을 직접 보여준다.
- [ ] 발표 중 네트워크 문제에 대비해, Phase 6에서 실연동한 API가 있다면 오프라인/키 만료 상황을 가정한 폴백이 실제로 동작하는지 발표 직전에 한 번 더 확인한다.
