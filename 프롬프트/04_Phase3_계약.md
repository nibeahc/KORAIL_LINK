# KORAIL LINK 빌드 프롬프트 세트 — Phase 3. 계약

> 전제: Phase 2 DoD를 통과했다(견적 확정 시 Cost Ledger가 저장된다). 지금 열어서 같이 읽을 문서: `기능_상세_스펙.md`의 B-2(참조 데이터 두 종류), B-6(계약 검토→초안→전자서명).

## 목표

견적이 확정된 Case에서 계약 탭으로 들어가, **근거를 먼저 보여준 뒤** 특약을 추천하고, 담당자가 검토·수정한 내용으로 계약서 초안을 만들고, 전자서명 상태 전환을 시뮬레이션한다. "AI가 계약서를 바로 뽑아준다"가 아니라 "왜 이 특약이 필요한지 먼저 보여준다"가 이 Phase의 핵심 차별점이다.

## 7-1. 협약 규칙 참조 데이터 — B-2 첫 번째 종류

Case와 무관하게 시스템에 **한 번만** 적재하는 고정 지식베이스다. Case마다 업로드하는 게 아니다.

- **SMGS 협약 원문(OSJD 발간)** 기준 핵심 항목을 구조화해서 코드/데이터로 만든다: 화물운송장 구성(원본·화물수령증·도착통지서 등 6매 + Duplicate Invoice, Art. 7.2/7.7), 첨부서류 요건(원산지증명서 등, Art. 22). 실제 협약 원문 전체를 넣을 필요는 없고, **이 노선(SMGS 단독 적용권 — 카자흐스탄·우즈베키스탄 종착)에 실제로 적용되는 조항만** 구조화한다.
- CIM/SMGS 관련 자료는 지금 노선에는 해당하지 않으므로(유럽 연장 시 필요) 이번엔 만들지 않는다 — 나중에 노선이 늘어날 때 확장할 자리로만 남겨둔다.
- 이 데이터는 "화물운송장 문서가 규칙을 충족하는지 검증할 근거"로만 쓴다(Phase 4에서도 재사용) — Case마다 다시 만들지 않는다.

## 7-2. 운송조건·규정·리스크 분석 → 특약 추천

입력: Case Master Data, 확정 견적/Cost Ledger, routePath(Phase 1), 7-1의 SMGS 참조 데이터.

특약마다 최소 아래 정보를 함께 표시한다 — **UI 카드에 이 5개 필드가 전부 보여야 한다**:

- `추천 특약`
- `적용 이유` — 어떤 노선/운송조건 때문에 필요한지
- `근거 유형` — 협약 / 계약조건 / 내부기준 / AI 리스크 권고
- `근거 출처` — 실제 지식베이스에 저장된 출처가 있을 때만 표시(없으면 표시하지 않는다, 지어내지 않는다)
- `반영 여부` — 담당자가 `반영 / 제외 / 수정` 중 선택

TCR 경유 노선은 SMGS 준수·궤간환적·정책변동 관련 특약이 추가로 붙어야 하고, 비TCR 노선은 기본 조항만 붙는다(routeData의 `usesTCR` 플래그로 분기). **근거가 없는 내용을 국제규정처럼 표현하지 않는다** — 출처 없는 항목은 `AI 리스크 권고` 또는 `내부 운영 검토 필요`로 명시한다(비타협 원칙 5).

## 7-3. 담당자 검토·수정 → 계약서 초안 생성

- 담당자는 각 특약을 `반영/제외/수정`하고, 필요하면 직접 특약을 추가할 수 있다.
- AI가 추천한 이유·근거는 계약서 본문에 반드시 들어갈 필요는 없다 — **검토 화면에서 의사결정 근거로만 제공**하고, 계약서 자체는 확정된 특약 텍스트만 담는다.
- 계약서 초안 = 확정된 특약 + Case Master Data + 계약금액. **별첨 1(구간별 운임 명세)은 Phase 2에서 저장한 Cost Ledger를 그대로 표로 옮긴 것**이어야 한다 — 총액을 다시 임의 비중으로 쪼개서 만들지 않는다(비타협 원칙 1). 이 단계에서 `contractAmount`(초기값=`quotedAmount`)를 Cost Ledger 각 라인에 채워 넣는다 — 이후 담당자가 협의 중 금액을 바꾸면 이 필드만 갱신한다(정산 Phase 5의 기준선이 된다).

## 7-4. 전자서명 시뮬레이션 — B-6의 4)

- `서명 요청 → 서명 완료` 상태 전환만 만든다(`none → pending → signed`, Phase 0 스키마 참고). 실제 전자서명 SDK 연동은 Phase 6(선택)에서 다룬다.
- 화면 어디에도 실제 법적 효력이 있는 것처럼 문구를 쓰지 않는다 — "서명 시뮬레이션"임을 명확히 한다.
- 서명 완료 후 해당 계약의 특약·계약금액·Cost Ledger(`contractAmount` 포함)를 **정산의 기준선으로 고정**한다 — Phase 5가 이 시점의 값을 그대로 조회한다.

## 완료 조건 (DoD)

- [ ] 계약 탭에 진입하면 계약서가 바로 나오지 않고, 먼저 "적용 규정·특약 근거" 화면이 보인다.
- [ ] TCR 노선 Case와 비TCR 노선 Case에서 추천 특약 개수·내용이 다르다(TCR 쪽에 SMGS 준수·궤간환적·정책변동 특약이 추가).
- [ ] 특약 카드에 5개 필드(추천 특약/적용 이유/근거 유형/근거 출처/반영 여부)가 전부 보인다. 출처 없는 항목은 "AI 리스크 권고"로 뜬다.
- [ ] 특약을 반영/제외/수정한 뒤 계약서 초안을 생성하면, 별첨 1의 구간별 금액이 Phase 2에서 저장한 Cost Ledger의 `quotedAmount`(또는 이 단계에서 수정한 `contractAmount`)와 정확히 일치한다.
- [ ] 서명 요청 → 서명 완료 상태 전환이 되고, Case 상태가 "계약"으로 바뀐다.
- [ ] 서명 완료 후 Cost Ledger의 `contractAmount`가 더 이상 이 화면에서 바뀌지 않는다(정산 기준선 고정 확인).

통과했으면 `05_Phase4_문서.md`로 넘어간다.
