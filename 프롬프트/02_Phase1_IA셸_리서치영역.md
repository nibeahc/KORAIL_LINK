# KORAIL LINK 빌드 프롬프트 세트 — Phase 1. IA 셸 · 리서치 영역

> 전제: Phase 0 DoD를 통과했다. 지금 열어서 같이 읽을 문서: `서비스_개요.md` 4장(서비스 이용 흐름·화면 구조 IA), `기능_상세_스펙.md`의 A-2, A-4, A-5, A-6, A-7, A-8.

## 목표

로그인 이후 사용자가 보는 전체 화면 뼈대(사이드바 IA)와, Case와 무관하게 항상 열람 가능한 "리서치" 영역(대시보드·시황·정보검색)을 만든다. 이 Phase가 끝나면 로그인해서 홈 화면을 보고, 시황 지표를 확인하고, 뉴스를 검색할 수 있어야 한다. 아직 견적/계약/문서/정산 화면은 만들지 않는다(껍데기 라우트만 두면 된다).

## 5-1. 사이드바 IA — 리서치 vs 파이프라인

`서비스_개요.md` 4장 "화면 구조(IA)"를 그대로 구현한다.

- **리서치**: 홈(대시보드) / 시황 / 정보 검색 — Case와 무관한 전역 화면.
- **파이프라인**: 견적 생성 / 화물 운송(아코디언, 하위에 계약·문서·정산) — Case 하나를 처리하는 액션 화면 묶음. 이 Phase에서는 라우트와 빈 화면만 만들고, 실제 내용은 Phase 2~5에서 채운다.

사이드바 하단에는 로그인한 사용자의 실제 이름·이메일(profiles 테이블 참고)을 표시한다.

## 5-2. 노선 데이터 — routeData.ts

먼저 이걸 만든다 — 이후 대시보드 KPI, 시황 카드 필터링, 견적서 자동생성(Phase 2), 계약 특약(Phase 3)이 전부 이 데이터에 의존한다.

- 목적지별(알마티·아스타나=카자흐스탄, 타슈켄트=우즈베키스탄, 비슈케크=키르기스스탄) 실제 구간 구성(`routePath.stages`): 코레일 철도 → 부산항 → 해상운송(→연운항) → TCR 환적 → 궤간 환적 → 중국 내륙철도 → 목적지. TCR 경유 여부에 따라 관련 시황 지표가 달라진다는 점을 데이터에 명시한다(예: `usesTCR: boolean`, `hasSeaLeg: boolean`).
- Phase 0에서 만든 목업 Case가 이 구조를 참조하도록 연결한다.

## 5-3. 시장 데이터 — marketData.ts (목업, 결정론적)

`기능_상세_스펙.md` A-2, A-8을 구현한다.

- 지표: USD/KRW, CNY/KRW, Brent 유가, USD/KZT, USD/UZS, USD/KGS, KCCI(종합), KCI(한중항로) — 총 8개 시계열, 각 30일치.
- **seed 고정 의사난수로 생성한다** (매 렌더링마다 값이 바뀌면 안 된다 — 하드코딩 배열이거나, seed 고정 생성 함수 둘 다 허용).
- **통화 표기 방향에 주의**: KZT/UZS/KGS는 "1 USD = 몇 현지통화" 방향이다(A-8). 값이 오르면 그 통화가 달러 대비 약세라는 뜻 — KRW 기준(오르면 강세)과 정반대이므로 헷갈리지 않게 변수명에 `usd` prefix를 붙인다(`usdKztSeries` 등).
- `detectAnomaly()`: zScore = (최신값−30일평균)/표준편차, `|zScore|≥2.0 OR |전일대비변동률|≥8%`면 이상탐지(A-2).
- `windowChangePct()`: 최근 구간 변화율 — Phase 2의 해상-철도 대체수요 서술(A-7)에서 재사용한다.

## 5-4. 뉴스 데이터 + 인과분석 — newsData.ts, causalAnalysis.ts

`기능_상세_스펙.md` A-4를 구현한다.

- 뉴스 카테고리 7종: TCR/연운항/환율/유가/통관/규제/지정학. 30건 정도 하드코딩.
- 일부 기사에 `indicator` 필드를 붙여 특정 환율·유가 지표와 연결한다(`matchNewsForIndicator()`가 이걸로 매칭).
- `causalAnalysis.ts`: 이상탐지 결과 + 매칭된 뉴스를 엮어 **결정론적 템플릿**으로 인과분석 문장을 생성한다(실제 LLM 호출 아님 — Part 0의 비타협 원칙 8 참고). Phase 5의 이의제기 챗봇이 이 함수를 재사용하므로, 지금 인터페이스를 깔끔하게 만들어둔다.
- **우선순위 반영**: A-4에 정리된 8가지 시황 요인 중요도를 화면 배치 순서에 그대로 반영한다 — 이벤트 기반 신호(정책·화차공급·지정학)를 정량 지표(유가·환율)보다 카드 순서상 앞에 둔다.

## 5-5. 계절성 — seasonality.ts

A-6. 화물 출발월이 1~2월(춘절 전후) 또는 11~12월(연말 성수기)이면 "성수기", 그 외는 "평시" — 캘린더 규칙, 시계열 아님. 노선과 무관하게 모든 Case에 적용.

## 5-6. 대시보드 — 홈 화면

A-5를 구현한다.

- **Case 상태별 분포(도넛)**: 상태(검증 대기/검토 필요/견적 확정/계약/정산)별 집계. Phase 0의 목업 Case로 지금 바로 테스트 가능하다.
- **KORAIL LINK 종합 지수**: 과거 견적(Phase 2에서 historicalQuotes를 만들기 전까지는 빈 배열/플레이스홀더로 두거나, Phase 2와 이 Phase 사이에 순서를 바꿔도 된다 — 판단은 네게 맡긴다)을 노선·컨테이너 타입 버킷별로 z-score 표준화 → 월별 평균 → ±1σ 밴드. **외부 지수처럼 보이지 않게 "자체 종합 지수"로 명확히 라벨링**한다(비타협 원칙 7).
- **KPI 스탯**: TCR 환적 경유 노선 수, 중국 내륙 직통 노선 수, 평균 리드타임 — routeData·Case 실데이터에서 계산.
- 시황 카드(8개 지표) + 브리핑 항목 클릭 시 근거 뉴스·인과분석을 보여주는 팝업(EvidenceDrawer).

## 5-7. 시황 화면 + 정보 검색 화면

- 시황 화면: 8개 지표 시계열 차트, 이상탐지 하이라이트.
- 정보 검색: 뉴스 통합 검색 + "이번 주 시황 브리핑" 카드(이상탐지된 지표 + 이번 주 이벤트성 뉴스, 정책·화차공급·지정학 카테고리 우선 — A-4 마지막 항목 참고).

## 완료 조건 (DoD)

- [ ] 로그인 후 홈 화면에서 Case 도넛·종합 지수·KPI·시황 카드가 전부 실제 계산 결과로 렌더링된다(하드코딩 숫자 아님 — marketData 값을 바꿔보고 화면이 바뀌는지 확인).
- [ ] 사이드바가 리서치(홈/시황/정보검색) / 파이프라인(견적 생성, 화물 운송 아코디언 하위 계약·문서·정산 — 빈 라우트라도 존재) 구조로 구현되어 있다.
- [ ] KZT/UZS/KGS 카드가 "1 USD = 몇 현지통화" 방향으로 표시되고, 상승=약세라는 설명이 화면 또는 툴팁에 있다.
- [ ] 이상탐지 조건(zScore 또는 변동률)을 만족하는 지표가 실제로 하이라이트된다 — marketData의 마지막 값을 극단적으로 바꿔서 이상탐지가 켜지는지 수동 확인.
- [ ] "KORAIL LINK 종합 지수"·KCCI/KCI 카드에 외부 공식 지수가 아니라는 라벨이 붙어 있다.
- [ ] TCR 경유 노선과 비TCR 노선(목업 Case 2건)에서 "현재 시장정보" 카드에 뜨는 지표 목록이 다르다(routeData 기반 필터링 확인).

통과했으면 `03_Phase2_견적생성_검증.md`로 넘어간다.
