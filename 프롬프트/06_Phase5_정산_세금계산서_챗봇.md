# KORAIL LINK 빌드 프롬프트 세트 — Phase 5. 정산 · 세금계산서 · 이의제기 챗봇

> 전제: Phase 4 DoD를 통과했다. 지금 열어서 같이 읽을 문서: `기능_상세_스펙.md`의 B-5(Invoice·정산 검증), B-7(세금계산서 자동생성), B-8(이의제기 챗봇).

## 목표

운송 완료 후 Invoice를 업로드하면, 총액이 아니라 **Cost Ledger 항목별로** 대조해서 차액의 원인을 보여준다. 그 결과로 세금계산서를 자동 생성하고, 정산 탭에서 담당자가 챗봇에게 "왜 이렇게 나왔는지" 물어보면 이미 계산된 근거를 그대로 인용해 답하게 만든다.

## 9-1. Invoice 업로드 + 라인아이템 매칭 — B-5

- Invoice도 Phase 4와 같은 문서 추출 시뮬레이션 방식으로 라인아이템(비용 항목 + 금액)을 추출한다.
- **1차 기준은 `계약 총액 vs Invoice 총액`이 아니라 `Cost Ledger(계약 기준 항목) vs Invoice 라인아이템`의 항목별 비교다.** 총액 비교는 화면 최상단 요약으로만 유지한다.
- 계약 확정 시(Phase 3) Cost Ledger 각 라인에 채워진 `contractAmount`가 이 매칭의 기준선이다 — 정산 단계에서 이 값을 다시 계산하지 않는다.
- 매칭 결과 분류:
  - 매칭 성공 → `계약금액 / Invoice 청구금액 / 차액` 표시
  - 금액 차이(크기 무관, 허용오차 없음) → `확인 필요`
  - Invoice에만 존재 → `계약 미등록 신규 항목`(BAF·THC·서류비 등)
  - Cost Ledger에는 있으나 Invoice에 없음 → `미청구/누락 확인`
  - 자동 매칭 불확실 → 임의 연결하지 않고 `매칭 확인 필요`
- 정산 요약: Invoice 총액(라인 합계) / 계약 총액(`contractAmount` 합계) / 총 차액 / 차액 발생 항목 수 / 신규 청구 항목 수. **총 차액 자체보다 "어느 항목 때문에 달라졌는지"를 화면 위쪽에 우선 표시한다.**

## 9-2. 세금계산서 자동 생성 — B-7

- B-5의 정산 대조가 끝난 뒤, 그 결과(Invoice 라인아이템)를 그대로 활용해 공급가액을 계산한다 — **별도 데이터소스를 두지 않는다**(정산 화면과 세금계산서 화면의 숫자가 항상 일치해야 한다).
- 필드: 공급자(코레일)·공급받는자(화주) 사업자번호(목업 고정값 — 상호명 기반 해시 등으로 생성), 작성일자, 품목("국제운송용역"), 과세유형, 공급가액, 세액, 합계금액.
- **과세유형 기본값은 영세율(세액 0원)이다.** 부가가치세법상 국외공급·외국항행용역은 영세율 대상이고 이 서비스의 핵심 시나리오(국제복합운송)가 여기 해당한다 — 공급가액의 10%를 기계적으로 계산하지 않는다. 세액 0원을 숨기지 말고 그대로 보여주되, **"국제운송용역 기준(실제 적용은 세무 담당자 확인 필요)"** 문구를 화면에 함께 표시한다.
- 실제 국세청 홈택스 연동이 아니라 미리보기·다운로드 시뮬레이션이다 — 이 사실을 화면 문구에서 과장하지 않는다.
- Phase 0에서 만든 `tax_invoices` 테이블에 생성 결과를 저장하고, 정산 탭에서 이력을 조회·재표시할 수 있게 한다.

## 9-3. 이의제기 챗봇 — B-8

- **실제 LLM 호출이 아니다.** 이미 계산된 판정 근거를 규칙 기반(키워드 매칭)으로 골라 답한다 — Phase 1의 `causalAnalysis.ts`와 같은 "결정론적 템플릿" 철학이다.
- 정산 탭에서 사용 가능. 답변 소스는 전부 이미 계산되어 있는 데이터를 재사용한다 — 새로운 데이터를 만들지 않는다.
  - "왜 비싸/높음/이상" → Phase 2의 σ 판정 근거 + Phase 1의 인과분석 설명
  - "차액/얼마/왜 달라" → 9-1의 Invoice-계약 차액 + 신규 항목(BAF·서류비 등) 목록
  - "왜 늦어짐/지연" → 관련 노선의 TCR·연운항 뉴스(Phase 1의 newsData)
  - 매칭 실패 → "정확한 답변을 드리기 어렵습니다. 담당자에게 문의해주세요"로 폴백 — **없는 답을 지어내지 않는다.**
- 모든 답변에 "어떤 판정·데이터에서 나온 답인지" 근거를 함께 표시한다 — 챗봇이 임의로 답한다는 인상을 주면 안 된다(Phase 2의 A-1 판정 문구 설계 원칙과 동일).
- 대화는 `dispute_chat_messages` 테이블에 저장한다(Phase 0).

## 완료 조건 (DoD)

- [ ] Invoice를 업로드하면 계약 기준 Cost Ledger와 항목별로 비교한 표가 뜬다 — 5가지 판정(일치/확인필요/신규항목/누락/매칭불확실)이 전부 실제로 재현 가능하다(테스트용 Invoice 데이터를 다르게 만들어 각 케이스를 확인).
- [ ] 정산 요약이 "총 차액"보다 "차액을 만든 항목"을 먼저 보여준다.
- [ ] 세금계산서 공급가액이 정산 화면의 Invoice 총액과 항상 일치한다(같은 소스 확인).
- [ ] 세금계산서 세액이 기본적으로 0원(영세율)이고, "실제 적용은 세무 담당자 확인 필요" 문구가 화면에 있다.
- [ ] 이의제기 챗봇에 "왜 비싸요", "차액이 얼마예요", "왜 늦어져요"를 각각 입력했을 때 서로 다른 근거를 인용한 답이 나오고, 답변에 근거 출처가 함께 표시된다.
- [ ] 챗봇에 매칭 안 되는 질문을 하면 "담당자에게 문의해주세요"로 정직하게 폴백한다(그럴듯한 답을 지어내지 않는다).
