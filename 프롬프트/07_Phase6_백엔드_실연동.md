# KORAIL LINK 빌드 프롬프트 세트 — Phase 6. 백엔드 실연동 (선택)

> 전제: Phase 5 DoD를 통과했다 — 여기까지만 해도 데모가 가능한 완결된 제품이다. 이 Phase는 **시간이 남을 때만** 진행한다. 지금 열어서 같이 읽을 문서: `백엔드_연동.md` 전체, 특히 1~7번 항목과 "LLM 벤더 선정 관련 메모".

## 목표

Phase 0~5까지는 전부 목업/시뮬레이션이 정상 동작하는 상태다. 이 Phase는 그중 일부를 실제 외부 연동으로 바꾼다. **전부 다 할 필요 없다** — 아래 우선순위를 참고해서 시간이 되는 만큼만 한다. 하나도 안 해도 Phase 7로 넘어가는 데 문제없다(그 경우 Phase 7에서 "이건 시뮬레이션입니다" 라벨을 화면에 명확히 하는 것으로 대체한다).

## 10-1. 권장 우선순위 (해커톤 시간 제약 고려)

효과 대비 공수를 기준으로 정렬했다. 위에서부터 순서대로 시도한다.

1. **환율 API (백엔드 연동 1번)** — 한국수출입은행/한국은행 ECOS는 API 키 발급이 빠르고 문서가 잘 되어 있다. USD/KRW, CNY/KRW부터 붙이고, KZT/UZS/KGS는 국내 API가 커버 못하면 exchangerate.host 등 해외 API로 보완한다. **가장 공수 대비 효과가 좋다** — z-score 이상탐지·인과분석이 실제 최신 데이터로 작동하는 걸 바로 보여줄 수 있다.
2. **유가 API (2번)** — Brent 유가는 EIA API가 무료고 안정적이다. 1번과 같은 패턴(`marketData.ts`의 시리즈 하나를 API 결과로 교체)이라 추가 공수가 적다.
3. **뉴스 API (4번)** — 네이버 뉴스 검색 API가 가장 빠르다. 다만 카테고리 자동 분류(TCR/연운항/환율/유가/통관/규제/지정학)와 `indicator` 필드 매칭까지 하려면 시간이 걸린다 — 시간이 부족하면 "검색은 실 API, 카테고리·인과분석 매칭은 기존 목업 뉴스 유지"로 절충해도 된다.
4. **해상운임 지수 API (3번, KCCI/KCI)** — 공식 API 유무가 확인 안 됐다(백엔드 연동 문서 참고). 담당자가 KOBC에 먼저 문의해야 하므로, 해커톤 중에 붙이기 가장 불확실한 항목이다. 실패 가능성이 있으니 우선순위 뒤쪽에 둔다.
5. **AI 문서 추출 (5번) / 이의제기 챗봇 (6번)** — 가장 임팩트가 크지만 공수도 가장 크다. 시도한다면:
   - LLM 벤더를 먼저 정한다(백엔드 연동 문서의 "LLM 벤더 선정 관련 메모" 참고 — 이전 메모마다 Claude/미정/OpenAI로 표현이 갈렸으니, 지금 이 시점에 하나로 확정하고 `.env`에 그 벤더 기준으로 키 이름을 통일한다).
   - **5번(문서 추출)보다 6번(챗봇)이 훨씬 쉽다** — 챗봇은 이미 구조화된 데이터(σ 판정, 인과분석, Invoice 차액)를 프롬프트에 넣고 자연어로 답하게만 하면 되지만, 문서 추출은 실제 PDF/이미지 파싱 + 스키마 강제 출력이 필요해서 더 오래 걸린다. 시간이 부족하면 6번만 실연동하고 5번은 시뮬레이션으로 남긴다.
6. **전자서명 SDK (7번)** — 데모 관점에서 우선순위가 가장 낮다. 지금 시뮬레이션(상태 전환)만으로도 시연 효과는 충분하고, 실제 SDK 연동은 계정 개설·웹훅 인프라 등 부가 작업이 많다. **시간이 정말 넉넉할 때만** 시도한다.

## 10-2. 항목별 작업은 `백엔드_연동.md`를 그대로 따른다

각 항목의 "필요한 작업 / 후보 연동 대상 / 연결 지점"은 이미 문서에 정리되어 있으므로 여기서 재복사하지 않는다. 이 프롬프트에서 추가로 강조할 것만 적는다.

- **모든 API 연동은 서버 사이드(Cloudflare Workers 라우트)에서 하고, 키는 절대 클라이언트에 노출하지 않는다.** 프런트는 `fetch('/api/...')`만 호출한다.
- **API가 실패해도 화면이 깨지면 안 된다.** Phase 0의 "로컬 우선 + best-effort" 원칙을 외부 API에도 그대로 적용한다 — API 호출 실패 시 마지막으로 성공한 값이나 목업 값으로 폴백하고 토스트로만 알린다. 데모 중 네트워크가 불안정해도 화면이 하얗게 뜨면 안 된다.
- **연동한 지표는 화면에서 "실시간 연동" 라벨로 바꾸고, 연동 안 한 지표는 계속 "자체 산출/시뮬레이션" 라벨을 유지한다** — 비타협 원칙 7(목업은 목업이라고 라벨링)이 이 Phase에서 가장 중요해진다. 일부만 실연동했는데 전체가 실시간인 것처럼 보이면 안 된다.

## 완료 조건 (DoD)

- [ ] 시도한 항목마다 실제로 최신 데이터가 들어오는지 확인했다(API 응답을 콘솔에 찍어서 값이 어제와 다른지 확인).
- [ ] API 키가 클라이언트 번들에 노출되지 않는다(`grep`으로 빌드 결과물에 키 문자열이 없는지 확인).
- [ ] API를 일부러 실패시켜봤을 때(잘못된 키로 테스트 등) 화면이 깨지지 않고 폴백 값 + 토스트로 처리된다.
- [ ] 실연동한 지표와 여전히 시뮬레이션인 지표가 화면에서 라벨로 구분된다.
- [ ] 이번 Phase에서 시도했지만 실패했거나 시간이 없어 건너뛴 항목이 있다면, 어떤 항목을 왜 건너뛰었는지 한 줄로 기록해둔다(Phase 7의 "알려진 한계" 정리에 그대로 쓴다).

통과했으면(또는 이 Phase를 건너뛰기로 했으면) `08_Phase7_통합QA_데모준비.md`로 넘어간다.
